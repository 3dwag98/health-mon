How fresh is each worker's health signal?

Each line is one worker over the last few minutes. It plots how old the worker's own evidence already was at the moment health last looked at it. Low and flat is good. A rising line means health is describing a worker it has not heard from recently — the green light is going stale, even if it still says green.

What changed, and when

Every time a worker's overall verdict changed. This is where detection and recovery show up: inject a fault and a line appears within a few seconds; clear it and the recovery line follows.

How to read this page

The four states

ok
Processing normally. Everything it needs is reachable.
degraded
Still working, but something non-essential is broken — a cache, a vendor API, low disk. Traffic keeps flowing here on purpose.
failing
Cannot safely process work. Something essential is down, or the worker is stuck. This is the one to act on.
starting
Booting. Dependencies have not all answered yet. Normal for the first 20–30 seconds after a restart.

The "how we know" column

observed
Strongest. The worker's own real queries and commands succeeded just now. Nothing was faked to find out.
introspected
Read from the worker's own connection state — pool counters, consumer registration — without sending anything.
probed
Weakest. Nobody used this dependency recently, so health sent a test request of its own. A probe proves the server answers; it does not prove the worker's own connection works.

The graphs

Response time (per dependency row)
The last ~3 minutes of check latency for that one dependency. Watch for a step change, not the absolute value — a flat line that suddenly climbs is the early warning.
Signal freshness (bottom left)
How far behind the worker the health data is. Flat and low means the verdict is current. Rising means it is getting old.
What changed (bottom right)
The state-change log. Silence here is good news.

Worth trying

Pause load
A worker with nothing to do must stay green. Any health system that alerts on an idle queue gets ignored within a week — press this and watch nothing happen.
Burst 2000
Builds a backlog. Queue depth climbs, the workers drain it, and the "waiting in queue" tile falls back to zero.
Fault injection
Run a docker compose exec toxiproxy command from the README and watch the "how we know" column flip from observed to probed, then the state go red.
